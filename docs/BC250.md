# Profil unique : BC-250

Cette implémentation n’emploie aucun autre système d’inférence. Environnement connu : SkillFishOS, RADV GFX1013, Vulkan, environ 8 Gio de VRAM déclarée et mémoire UMA/GTT ; la mémoire réellement disponible doit être observée sur la machine. Le chemin historique du binaire est `/home/bc/.unsloth/llama.cpp/llama-server`. Son emplacement dans un dossier Unsloth ne constitue pas une dépendance à Studio : le binaire est appelé ou interrogé directement.

## Réutiliser sans ralentir

Priorité au processus résident : pas de chargement de modèle supplémentaire, pas de changement de quantification, même backend Vulkan. `scripts/bc250_runtime.py discover` inspecte `/proc` sans afficher les clés. `manifest` calcule les SHA du binaire/GGUF. `scripts/bootstrap-local.py` récupère le port et la clé localement, vérifie le template et écrit une configuration protégée ; aucune requête à l’API Studio.

Un processus déjà lancé par Studio reste dépendant de son gestionnaire pour sa durée de vie. L’application n’utilise plus Studio pour ses appels, mais cela ne transforme pas ce processus en service indépendant. Pour une indépendance de cycle de vie complète, `deploy/bc250-llama.service` peut gérer le même binaire et le même GGUF. Il refuse de démarrer si un autre llama-server est présent ; aucun processus existant n’est tué automatiquement. Le service se lance sous `bc` pour accéder aux modèles et au périphérique Vulkan existants.

Profil indépendant initial : contexte 4096, un slot, batch 512, microbatch 128, KV F16. Ces réglages reprennent le cadre connu ; aucun gain chiffré n’est revendiqué. Le KV quantifié n’est pas activé sans mesure qualité/mémoire préalable. Aucune reconstruction, OCR ou validation déterministe ne consomme un second modèle GPU.

## Contrat réellement vérifié

Au premier appel : `/props` doit annoncer un template comportant les champs langue source/cible ; `/apply-template` rend le prompt ; `/tokenize` compte les tokens avec le tokenizer chargé ; `/completion` retourne la traduction. Un runtime trop ancien ou un modèle incompatible provoque un échec explicite. Le SHA configuré est une attestation issue du fichier local ; il ne constitue pas une preuve distante cryptographique que le processus ne changera jamais de poids. Interdire les changements de modèle pendant les jobs et créer un nouveau job après changement du contrat.

Les blocs sont découpés aux frontières de phrases, puis aux espaces en dernier recours. La limite de 1800 tokens d’entrée tient compte du template et reste sous les 2K annoncés par TranslateGemma ; 4096 est le contexte total du serveur, pas une autorisation de 4096 tokens d’entrée. Température zéro et seed enregistrés n’assurent pas l’identité bit à bit entre versions de runtime.

## Réseau

Endpoint loopback si co-localisé, IP privée explicite si application Ubuntu sur le LAN. Le client refuse les adresses publiques et les noms DNS arbitraires ; proxy d’environnement et redirections désactivés. Le moteur expose une clé locale ; si écoute LAN, firewall limité à l’hôte applicatif. Ne jamais publier le port LLM via Cloudflare.

Comparer sur la machine les mêmes unités, cache froid/chaud, temps préfill/génération, VRAM/GTT et erreurs, via le benchmark réel. Le passage direct contourne une couche HTTP de Studio ; il n’a pas encore été chronométré sur cette BC-250 depuis ce nouvel environnement.
